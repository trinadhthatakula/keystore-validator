Goals

  • Read and display signing certificate fingerprints from a supplied JKS keystore.
  • Inspect an APK signature and compare its verified signing certificate with a selected keystore certificate.
  • Keep APKs, keystores, private keys, and passwords in the browser while hosting the application on a Vercel Hobby account.

Included

  • Browser-local JKS inspection and alias selection
  • Browser-local APK signing certificate inspection and signature verification
  • SHA-256 certificate comparison with clear match, mismatch and unverifiable outcomes
  • Hobby-compatible static deployment and privacy-focused user experience

Excluded

  • Signing or modifying APKs
  • Uploading files, passwords, or private keys
  • Account creation, database, server-side file handling, or long-term storage
  • AAB inspection and Play Console integration for the initial release
  • Claiming APK install/update compatibility merely from matching a certificate

Features

Read the selected JKS in a worker; request only the store password and expose aliases with public certificates.

must confirmed

Acceptance criteria

  • Detect and report unsupported or corrupt files without exposing secrets; validate JKS integrity when a password is provided and distinguish an incorrect password or integrity failure.
  • List certificate-bearing aliases; allow selection and display subject, issuer, validity dates, certificate SHA-256 and SHA-1 fingerprints.
  • Do not request a separate private-key password or decrypt or export private keys just to display certificates.
  • Compare generated fixture results against keytool -list -v, including multiple aliases, trusted-certificate entries and wrong passwords.

Dependencies: Not specified

Read the APK locally, verify supported Android signing schemes and show verified signer certificate details.

must confirmed

Acceptance criteria

  • Show SHA-256 and SHA-1 certificate fingerprints and scheme verification results for each active signer if available; label certificate extraction and signature validity separately.
  • Verify applicable v1/v2/v3/v3.1 signatures and APK contents within the explicitly stated Android API range; unsupported schemes, rotation, malformed, tampered, unsigned and ambiguous cases must be identified and never reported as verified.
  • Cross-check verification results and signer fingerprints against official apksigner fixtures for supported API ranges, including valid, tampered, unsigned, multi-signer and rotated-key inputs.
  • Handle APK files of at least 100 MB on tested target browsers; report progress, allow cancellation and return a clear resource-limit error when needed.
  • Consider the verifier overall result and content integrity; individual signer verified flags alone cannot establish that an APK verifies.

Dependencies: Not specified

Compare the selected keystore certificate to the verified APK signer certificate locally.

must confirmed

Acceptance criteria

  • Use SHA-256 of the DER-encoded signing certificate for canonical identity; SHA-1 is display-only.
  • Show matched, mismatched, and unverifiable states; never assert signature validity or a successful verified match solely because an extracted certificate fingerprint matches.
  • For multiple signers or rotation show each signer and whether the selected certificate is active or historical; do not imply Android update compatibility from a single matching signer.
  • Explain Google Play app-signing keys versus upload keys when relevant.

Architecture

Vercel serves a static TypeScript web UI and same-origin worker/WASM assets. User-selected APK and keystore bytes are read locally, with no file-processing backend. A verified browser-capable signing engine remains a required feasibility gate.

ComponentPurpose
Vercel static hostingDeliver first-party HTML, CSS, JavaScript and reviewed local WASM assets over HTTPS.
Browser UICollect files and store password locally, render progress and alias choices, and display signer and matching outcomes.
Browser workerOwn ephemeral local parsing, fingerprint calculation, cancellation and controlled error handling.
Signing inspection engineCandidate JKS and APK verifier implementations; must pass feasibility, security, memory and differential tests before selection.

Constraints

Security and privacy

  • Private keys and passwords must never leave the browser. APKs and keystores are processed locally.
  • Avoid private-key decryption for certificate inspection; no secrets in telemetry, logs, URLs or persistent storage.
  • Treat the delivered site and its dependencies as part of the trust boundary; restrict scripts and network connections, review updates, and avoid claims of absolute security.

Performance

  • Support at least 100 MB APKs on measured desktop browsers, with worker responsiveness and bounded or clearly documented memory use.
  • Benchmark peak memory and time; browser memory constraints mean no universal size guarantee.

Accessibility

  • Keyboard access, semantic labels, visible focus and readable error/progress messages; verify in target browsers.

Localization

  • English initially as an assumption; use text resources that can later be localized.

Deployment

  • Deploy a static build to Vercel Hobby; do not rely on server functions to receive files.
  • Keep a preview release and verify assets and security headers before promotion.

Offline

Processing should continue without network after all app assets are loaded; installable/offline-first service worker is not required initially.

Monetization

No monetization requested; Hobby suitability for personal, non-commercial use must be checked before release.

Budget

Hobby account requested; usage-dependent bandwidth and build costs or limits must be checked against current Vercel terms.
